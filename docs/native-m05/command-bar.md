## Implemented composition

`windows::launcher::Launcher` now re-exports `surfaces::command_bar::Launcher`. Its existing constructor, public input/rows/ready/error/visible/zoom fields (`rows` retains shared `Arc<Row>` values, avoiding duplicate icon bytes), and query/show/hide calls remain available to the app and bench control. The surface uses the actual M3 `launcher::controller::Launcher`, `SearchSession`, `Row`/`Action`, argument validation, pins, recency/query history, router, update policy and instant functions. Core still owns ranking, scanners, app discovery, safety and core stores. There is no WebView, JS engine, Node/Pi execution path, or cloned core search implementation in this surface.

The native view includes home rows and a 12-slot pin rail, virtualized list and seven-column application grid, hidden Deep Search/app/terminal prefixes, path completion, AI prompt/cwd and restored-chat intents, terminal session selection and defaults, argument fields/dropdowns/password fields, argument contributions, result actions, pin picker and drag, query recall, calculator/colour/currency/emoji rows, selectable answer/action content, vault-copy feedback and status-driven updater rows. Native model selection uses M3's `settings::WriteQueue` merge against freshly read config. User model selection must finish saving before submission. Existing Quicklinks remain legacy core search/open-url actions; no CRUD/store was invented.

The source TS wins over a misleading ledger label: `CommandBar.tsx:4163` sends Cmd/Ctrl+H to Clipboard History. The native shortcut emits that typed navigation, not a new query-history toggle. Query recall remains Up on empty input. Mode hints are static without a rolling idle timer.

Render constructs native controls and registers event listeners; it starts no requests, processes, network operations or timers. GPUI's monotonic executor clock drives the model deadline. Committed-change events plus marked-text observation feed composition ownership, so a new composition cancels a queued Enter. Effects own requests, deferred activation, directory resolution, timers, persistence and icon admission. Buttons use the shared GPUI keyboard click behavior; intercepted command keys prevent the default keyboard click. No native OS actions are executed by the mocked tests.

Search and activation use model generations/tickets. Authoritative clicks carry the displayed generation; speculative rows cannot authorize an action. Directory resolution returns `DirectoryResolved` under its original ticket. AI, terminal and note navigation consume their model ticket while retaining the window for the destination. Hide cancels view waiters, clears composition/mode/input, releases icon textures and keeps the core event subscription alive to drain already-active producers. Reopen paints cached home rows and requests the current home generation. Invalidation retains its text filter and is decided by the repaired model; active argument contributions are refreshed under a separate argument revision.

`CoreClient::request` sends canonical public core channels and one `{action, context}` envelope for execute/usage, with row identity and one-based rank. Each admitted request owns a Tokio task independently of the GPUI waiter, bounded to 16 per client. Cancelling the waiter cannot interrupt a core write/effect halfway through. Completion logs contain success/error only, never arguments or payloads. Quick Look suppression and restoration are inside that same owned operation. Core startup/shutdown and their fixture ownership remain M4-owned.

Icon requests are effect-owned, admitted four at a time, limited to 120 displayed row requests and the existing foundation 128-entry/32 MiB cache. Data URLs and `asset-icon:data-url` go through bounded PNG decoding on background work. Replacement, hide and release clear view handles; the foundation releases GPU ownership. Search caches use the existing model's 1,000 candidates, 40 home rows and 24 × 100 query rows. No per-row task or timer runs while idle. Actual GPU pressure and matched full-app RAM remain unmeasured.

UI state uses `UiState::decode/write_atomic` at the explicit preview config path. Unknown keys survive, corrupt files are not overwritten, and writes are serialized/latest-revision owned. Writes and handled usage records survive view hide. Quit drains retained writes and checks the latest write error. No WebView storage discovery/import/deletion or production-profile reread is performed; that is M11.

## Stable app/destination contract

- `navigation::Navigation { nonce, surface: router::Surface, payload: Payload }` is the single destination handoff. `Payload` preserves AI prompt/cwd/resume/capture, terminal command/cwd/session/defaults, vault item ID, note `createdAt`, full extension result, new-item intent, Settings tab, and explicit update action.
- `Event::Navigate(Navigation)` retains it in `NavigationInbox`, calls `Launcher::receive_navigation`, and lets the app mount the destination owner. `NavigationInbox::pending/take(surface)` lets M6–M10 consume the matching intent exactly once. A destination's actual content is outside this lane. The current command-bar view retains the handoff and offers Back; that is not a claim of destination parity.
- `Navigation::from_core` maps canonical `app:open-surface` strings for core shortcut navigation. `run-extension-command-from-hotkey` uses the existing extension core request and hands its result to the runtime owner. Worker clipboard/open/scripts are **not replayed**; only fresh toast/HUD notices are presented through `WorkerRecords`.
- `Event::Reveal(String)` is a GPUI Host operation. `Event::Update(UpdateAction)` is resolved from the current `AppUpdateStatus`: ready → restart, available → download, manual → installer, checking/downloading → no-op, otherwise check. The isolated preview retains this action without contacting a live feed or replacing an app. M11 must install the updater consumer.
- `Launcher::core_ready(cx)` recovers the transport epoch and submits latest committed input. `drain_state() -> Vec<Task<()>>` plus `state_write_error() -> Option<String>` let the parent quit coordinator wait and reject failed saves before retirement.
- `Launcher::update_pointer_gesture(window, cx) -> Result<(), String>` and `end_pointer_gesture(cx)` are thin M4 hooks. Paint-time window listeners are ungated by row hover. Any mouse-up ends resize; motion with no left button also retires a missed release. Pin drop handling remains left-button-only. The drag handle only sends `SnapBegin`; it never calls `start_window_move`. The app owns OS drag/release tracking.
- `RequestAdapter::send(Request)` is the injected request seam for native tests. Tests exercise the real view, `TextInput`, model and effect methods; synthetic replies replace providers/OS actions, not the view/controller implementation.

`NativeLocale` uses Foundation's current OS locale/calendar/timezone for macOS currency, timestamp, relative and grouped-count presentation. Relative dates use calendar addition and a named relative-date formatter; the first direct-components attempt returned NULL for a week and is preserved as a failed regression log. Windows currency uses system ICU and the current user locale. Windows linking/locale output and Windows timestamp/count presentation still require their platform gate; no English-as-OS-locale assertion is made.

## Explicit remaining gaps

These prevent claiming all L/A/K rows green:

1. **Persisted pin outside current results:** model `Click` only admits rows in the active authoritative generation. Home pins execute normally, but an Alt slot whose pin is absent from that generation is not yet executable. Requested model contract: `Input::ActivatePin { row, rank }`, issuing the same normal activation ticket without authorizing optimistic rows or altering search ranking. This lane did not patch frozen model sources or introduce a second activation owner.
2. **Legacy answer event attribution:** `stream-token/done/error` carry no request owner. Hidden events are drained/ignored, but a previously emitted event queued across a new answer request cannot be attributed perfectly. Requested core contract: optional native owner on `query`, echoed by its stream events; callers without it retain their legacy string payloads. This lane did not modify core.
3. **Updater execution:** row presentation and status-to-action dispatch exist; the app preview retains the explicit typed action. Check/download/restart/installer execution awaits the M11 updater owner and cannot be called a completed updater action.
4. **Unrun UI acceptance:** exact light/dark screenshot comparison, real OS IME, VoiceOver/Narrator, physical keyboard layouts/Alt slots, native Quick Look/focus, tooltips, colour/icon pixel parity, GPU lifetime pressure, mixed DPI, and Windows build/GUI/locale checks remain open. The current model picker has native keyboard/provider/model choices and configuration routing, but does not yet reproduce the TS picker's search field/provider preview sub-navigation. These are visible M5 acceptance work, not silently accepted parity.
5. First-party text/clipboard transform engines and structured locale seams exist in M3; the command bar does not invent a new transform query syntax. Clipboard transform chips and their formatter consumption belong to M6; full extension/runtime behavior belongs to M9. Their screen rows are not marked implemented by this lane.

The per-row map records code/test evidence and these limits. The parent must not promote M5 as fully accepted while the listed gaps remain. Future destination screens (including approval/composer, notes formatting, clipboard/snippet/vault editing, rich terminal grid and Settings save UI) are intentionally M6–M10, not unsupported launcher commands.
