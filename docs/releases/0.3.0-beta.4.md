# Tezbar 0.3.0-beta.4

Release date: 2026-11-02

This beta gives the macOS app a persistent certificate signing identity so future updates can retain privacy permissions and access to the existing Vault Keychain entry.

## macOS updates

- Preserve the configured Apple Development certificate during beta packaging instead of replacing it with ad-hoc signing.
- Pin and verify the app identifier, signing team, and certificate requirement before producing release receipts. Stop packaging if an update changes that identity.
- Add project release rules and a regression test using two different certificate-signed builds, including rejection of ad-hoc output.
- Keep the existing Vault, settings, Keychain entries, and application identity paths.

Updating from beta.3 can require one final permission or Keychain approval because its old identity was tied to that specific binary. Subsequent releases using the new pinned identity should preserve those approvals.

## Beta distribution

The macOS app is certificate-signed with the existing Apple Development identity under Team ID `UBRTH86SZ3`; it is not Developer ID notarized. The Windows installer continues the beta exception without Authenticode signing. Both updater artifacts carry verified Tauri updater signatures matching the key already trusted by installed Tezbar versions.

Supported platforms: macOS Apple Silicon arm64 and Windows x64. No Intel Mac installer is included.
